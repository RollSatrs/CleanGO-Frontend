## Правила ведения
- Один этап = GitHub Issue; внутри чекбоксы задач. Закрывать задачу только после кода, тестов и подтверждения в приложении.
- Не отмечать ранее реализованное как проверенное без подтверждения. Ссылки на коммиты и тесты прикладывать в комментарии issue.
- Закрывать issue этапа после выполнения всех пунктов и критериев приёмки. После каждого изменения синхронизировать этот документ.
- Не проводить миграции живой PostgreSQL без резервной копии и согласования.
- Клиенту до принятия заказа показывать только агрегированную статистику предложений; не показывать GPS и личные данные клинеров. «Отправлено» не равно «Просмотрено».

## Реализация поездки клинера (2026-11-19)
- Код: после принятия заказа `accepted → en_route → arrived → in_progress → completed`, с серверной проверкой исполнителя и состояния.
- Клинер: маршрут до адреса клиента через Google Maps, кнопки изменения этапов и добровольное включение/выключение передачи геопозиции в пути.
- Клиент: карточка назначенного исполнителя, статусы прибытия и маркер клинера на карте только при явном согласии, свежих координатах и статусе `en_route`.
- Ограничения: передача координат работает только пока экран клинера открыт; нет фонового GPS, расчёта ETA, построения маршрута внутри CleanGo и push-уведомлений. Для продакшена нужны полевые тесты на Telegram iOS/Android, тесты доступа, тесты отказа GPS и проверка деплоя.

## Навигация и Telegram-уведомления — реализация 2026-11-19
- Добавлен запрос расчёта дорожного расстояния и ориентировочного времени поездки (OSRM public demo) по явному нажатию кнопки у клинера; клиент также может запросить ETA при включённом GPS клинера. Пробки не учитываются, маршрут не является гарантированным; внешний Google Maps остаётся основным навигатором.
- Backend: опциональные Telegram Bot API уведомления о предложении клинеру, принятии заказа клиенту, выезде, прибытии, начале и завершении уборки. Для отправки требуется `TELEGRAM_BOT_TOKEN` того же бота, через которого пользователи запускали Mini App; Telegram ID пользователя должен быть сохранён. Не логировать токен и не добавлять его в Git.
- Передача GPS в фоне при закрытом Telegram Mini App не реализована: WebView может остановить watchPosition. Для гарантированного background tracking нужен нативный Android/iOS клиент с разрешениями и политикой конфиденциальности.
- Открытые задачи: надёжная очередь отправки уведомлений после commit и повторные попытки, мониторинг delivery; продакшен маршрутизация с SLA/квотами вместо публичного OSRM; пошаговая навигация в собственном приложении; проверка Vercel и NestJS build/test.

## Чекап 2026-11-20 — уведомления и пилот

### Изменения в коде (требуют локального тестирования)
- Backend: форматированные HTML-уведомления Telegram с кнопкой перехода к боту, типом уборки, площадью, ценой и коротким номером заказа. Точный адрес не передаётся в предложении клинеру.
- Backend: авторизованный GET `/orders/notifications` возвращает события заказов клиента и предложения/события назначенного клинера с фильтрацией по владельцу.
- Frontend: колокольчик уведомлений, счётчик непрочитанных, список событий, обновление каждые 15 секунд при открытом Mini App. Отметки о прочтении пока локальные (localStorage), не синхронизируются между устройствами.
- Уведомления через Telegram пока best-effort: нет гарантированной доставки, retry/outbox, дедупликации, настройки согласия пользователя и мониторинга.

### Приоритеты до закрытого пилота
1. Проверить `pnpm build` и `pnpm test` для обоих репозиториев; проверить Vercel deploy.
2. На двух реальных Telegram-аккаунтах проверить создание заказа, одновременные предложения нескольким клинерам, гонку принятия, истечение 90 секунд, статусы и уведомления.
3. Проверить безопасность: изоляцию уведомлений по ролям, невозможность доступа к чужому заказу, приватность адресов, корректность подписи Telegram и JWT.
4. Доработать доставку уведомлений после фиксации транзакций, очередь повторов, дедупликацию и обработку отмены.
5. Завершить правила отмен, споров, модерацию клинеров, отзывы, поддержку и политику обработки персональных данных.
6. До реальных денежных операций: выбрать правовую форму, проверить налоги/ОКЭД, договоры, эквайринг, фискализацию, комиссию, возвраты и выплаты с профильным специалистом.
