# CleanGo — MASTER ROADMAP: от MVP до коммерческого запуска

Обновлено: 2026-11-19. Это **основной долгосрочный план**; исторический `CLEANGO_ROADMAP.md` сохранён без изменений.

## Правила ведения
- Один этап = GitHub Issue; внутри чекбоксы задач. Закрывать задачу только после кода, тестов и подтверждения в приложении.
- Не отмечать ранее реализованное как проверенное без подтверждения. Ссылки на коммиты и тесты прикладывать в комментарии issue.
- Закрывать issue этапа после выполнения всех пунктов и критериев приёмки. После каждого изменения синхронизировать этот документ.
- Не проводить миграции живой PostgreSQL без резервной копии и согласования.
- Клиенту до принятия заказа показывать только агрегированную статистику предложений; не показывать GPS и личные данные клинеров. «Отправлено» не равно «Просмотрено».

## Зафиксированные будущие функции (не забыть)
- **Профили:** этап 03, базовые карточки клиента и клинера — этап 02.
- **Уведомления:** этап 02, через Telegram о важных изменениях заказа; в будущем push для мобильных приложений (этап 09).
- **Оценки и рейтинги:** этап 03, только после завершённого заказа, с проверкой принадлежности заказа и защитой от повторных оценок.
- **Текущий UX поиска:** отдельный issue, часть этапа 02. Не считать выполненным без тестирования в Telegram.

## Вехи бизнеса
- **После этапа 3:** рабочий MVP при условии успешных сквозных проверок.
- **Этап 5, до коммерческих операций:** определить и оформить ИП или ТОО с учётом законодательства Казахстана, налогов, договоров, платежей и возраста/дееспособности учредителя. Конкретный момент уточнить с юристом/бухгалтером; юридическую подготовку начинать заранее.
- **После этапа 6:** готовность к ограниченному коммерческому пилоту при соблюдении юридических и операционных требований.
- **После успешного этапа 7:** решение о публичном запуске.
- **Этапы 8–9:** запуск и масштабирование.
